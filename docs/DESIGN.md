## 1. 개요

### 1.1 목적
성경 본문을 읽고, 구절을 기준으로 말씀 나눔 초안, 삶에 닿는 예시, 가벼운 한마디를 얻을 수 있는 모바일 앱(Android, iOS)이다. 사용자의 원고와 기록은 모두 기기 안에만 저장한다.

### 1.2 범위
- **플랫폼**: Android(7.0, API 24 이상)와 iOS(15 이상) 앱. 하나의 웹 코드(TypeScript, React)를 Capacitor로 감싸 두 플랫폼 앱으로 만든다(2.1.2). 같은 정적 빌드는 개발·자동 테스트용으로 브라우저에서도 열 수 있다. 데스크톱 전용 인터랙션(호버, Shift 클릭)은 구현하지 않는다.
- **포함(MVP)**: 본문 뷰어(롱터치 선택), 구절 검색, 내 설교에서 찾기, 말씀 구성표(LLM 없음), 가벼운 한마디와 삶에 닿는 예시 라이브러리(LLM 없음), 설교 원고 업로드와 저장, 페르소나 선택, LLM 연결(사용자 API 키), 말씀 나눔 초안과 삶에 닿는 예시 생성, 로컬 백업 내보내기와 가져오기
- **제외(MVP)**: 서버, 회원 가입, 계정 동기화, 결제, 커뮤니티 공유, 의미 기반(임베딩) 검색, 데스크톱 전용 UI

### 1.3 핵심 원칙
1. **서버가 없다.** 앱 파일(정적 웹 자산과 본문 DB)은 앱 패키지 안에 넣어 배포하고, 실행은 전부 기기 안에서 한다.
2. **독립 모드가 기본이다.** LLM 키가 없어도 본문, 원고 관리, 구성표, 라이브러리가 모두 동작한다.
3. **외부 통신은 LLM 호출뿐이다.** 분석 도구, 원격 로그, 외부 폰트나 스크립트 등 다른 외부 요청을 두지 않는다. 호출 대상은 사용자가 선택한 제공자의 공식 API 엔드포인트로 한정한다.
4. **본문은 기억이 아니라 데이터에서 온다.** LLM이 성경 구절을 임의로 쓰지 않는다. 인용은 기기 안의 본문 DB 원문을 프롬프트에 넣어 처리한다.
5. **사용자 비밀번호를 받지 않는다.** LLM 연결은 공식 API 키 입력만 허용한다.
6. **생성물은 초안이다.** 결과 화면에 검토 안내를 표시한다.

## 2. 구조 개요

### 2.1 배포와 실행
```
[정적 웹 자산: HTML, JS, CSS, 본문 DB(sql.js용 bible.sqlite)]
          │  (Capacitor 앱 패키지 안에 포함, 설치 직후부터 오프라인 동작)
          ▼
[기기 안 실행 환경: 앱의 WebView (Android System WebView / iOS WKWebView)]
   ├─ 본문 저장소     → 번들된 bible.sqlite 읽기 전용 (sql.js, WASM)
   ├─ 사용자 저장소   → IndexedDB (원고, 청크, 페르소나, 라이브러리, 캐시, 키 묶음)
   ├─ 보관 모듈       → WebCrypto 암호화 (키는 non-extractable CryptoKey)
   ├─ 독립 엔진       → 참조 파서, 발췌 검색, 구성표, 라이브러리 검색
   └─ LLM 클라이언트  → 제공자 API 직접 호출 (사용자 키, 선택 기능)
          │  HTTPS (제공자 공식 엔드포인트만)
          ▼
      [Gemini / OpenAI / Anthropic 등 제공자]
```

- 중계 서버, 데이터베이스 서버, 큐, 스케줄러가 없다.

#### 2.1.2 앱 패키징 (Capacitor)
- 도구: Capacitor 8(`@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/ios`). 요구 환경은 공식 문서 기준 Node 22 이상, Android Studio 2025.2.1 이상(minSdk 24, compile·targetSdk 36), Xcode 26 이상(iOS 15 이상, 의존성 관리는 SPM). 확인일 2026-11-05.
- 웹 자산은 `npm run build:app`(앱 모드 빌드)으로 `dist/`에 만들고 `npx cap sync`로 `android/`, `ios/` 프로젝트에 복사한다. 앱은 실행 중에 웹 자산을 내려받지 않는다(원격 `server.url` 금지).
- WebView 출처는 Capacitor 기본값(Android `https://localhost`, iOS `capacitor://localhost`)을 쓴다. IndexedDB, WebCrypto, WASM은 이 출처에서 그대로 동작한다. 앱을 지우면 기기 안 데이터도 함께 지워진다.
- 앱 모드에서는 서비스 워커를 등록하지 않는다(자산이 이미 패키지 안에 있고, 앱 업데이트 후 오래된 캐시가 남지 않게 한다). 브라우저 빌드는 PWA 설정을 그대로 둔다.
- CSP는 웹 빌드와 같다(`connect-src 'self'` + 제공자 엔드포인트). 앱 네이티브 HTTP 플러그인(`CapacitorHttp`)은 켜지 않는다. 모든 요청은 WebView의 `fetch`로 하고, 외부 요청 제한 규칙(1.3-3)을 그대로 지킨다.
- 파일 내보내기(백업 파일, txt 샘플 양식)는 앱에서 `<a download>`가 동작하지 않으므로, 앱 안 임시 파일로 쓴 뒤 기기 공유 시트로 넘긴다(`@capacitor/filesystem`, `@capacitor/share`). 사용자가 저장 위치나 보낼 곳을 고른다. 앱이 스스로 외부로 보내지 않는다. 브라우저 빌드는 기존 내려받기를 쓴다.
- 파일 가져오기(원고, txt 역본, 백업 파일)는 `<input type="file">`을 그대로 쓴다(WebView 파일 선택기).
- 외부 링크(발급 안내, 역본 안내)는 사용자가 누를 때만 기기 기본 브라우저로 연다. 앱 안 WebView로 외부 페이지를 열지 않는다.
- 앱 식별자 `app.opensermon.meditation`(가칭), 앱 이름은 i18n `app.title`과 같은 "말씀 묵상". 서명 키와 스토어 등록은 사용자가 한다.
- iOS 빌드는 macOS와 Xcode가 필요하다. 이 저장소에는 `ios/` 프로젝트만 두고, 빌드와 실기기 확인은 수동 항목이다.

#### 2.1.1 번들 본문 DB (파생 빌드)
- 원천: `crizin/bible-db` 릴리스 `v1.0.1`의 `bible.sqlite.gz`(54.7MB, 풀면 131.5MB). 원본에는 원어 본문, 원어 사전, 의미 벡터(sqlite-vec `vec0` 가상 테이블) 등 앱이 쓰지 않는 데이터와 CC BY-SA 데이터가 들어 있어 그대로 번들하지 않는다.
- 개발자가 `npm run db:build`(`scripts/build-bible-db.mjs`)를 실행하면 원본 `.gz`의 SHA-256을 `config`의 `bible_db.release_sha256`과 대조한 뒤, `books`와 `verses` 중 `source IN ('krv','kjv')`만 새 DB로 옮겨 `public/data/bible.sqlite`를 만든다. 같은 원본이면 같은 파일이 나온다(파생 해시 `bible_db.sha256`).
- 파생 스키마: `books(book, code, name_kr, testament)`, `verses(source, book, chapter, verse, text)`(기본 키 `source, book, chapter, verse`), `build_info(key, value)`. 본문은 원본 문자열을 바꾸지 않는다(개역한글 동일성 유지).
- 크기: 9.8MB(gzip 3.1MB). 앱 실행 중에는 원본을 받지 않는다.
- 운영자가 사용자 데이터에 접근할 방법이 없다. 이는 설계상의 장점이자 제약이다(7장 참고).

### 2.2 LLM 경로의 제약 (반드시 검증 필요)
- **브라우저 직접 호출 지원 여부**: 각 제공자가 브라우저에서 직접 API를 호출하는 것을 허용하는지 구현 전에 공식 문서로 확인해야 한다. 허용하지 않거나 CORS 설정이 없는 제공자는 웹 경로에서 쓸 수 없다. 이 경우 사용자가 설치하는 래핑 앱(예: Capacitor 계열)으로 만들면 웹 CORS 제한을 피할 수 있으나, 이는 "서버 중계"가 아니라 앱 내부 호출이어야 한다.
- **공용 키 불가**: 서버가 없으므로 운영자의 무료 키를 앱에 넣을 수 없다. 키를 넣으면 누구나 꺼내 쓸 수 있다. 따라서 기본 경로는 **사용자가 자신의 무료 키를 발급받아 입력하는 방식**이다.
- **확인 결과(2026-11-05, S07, `docs/PROVIDERS.md`)**:
  - Anthropic: 공식 문서에 CORS 조건(`anthropic-dangerous-direct-browser-access: true` 헤더)이 적혀 있어 사용할 수 있다. 단, ZDR·Compliance API가 켜진 조직은 브라우저 호출이 막힌다(401).
  - OpenAI: 공식 문서가 브라우저 노출을 금지한다.
  - Gemini: 공식 문서 본문을 확인하지 못했다. → **v0.19에서 변경**: 사용자 제공 메모를 공식 가이드로 간주하고(사용자 결정 2026-11-06), 앱 WebView에서 CORS 호출을 실기기로 확인해 사용할 수 있다. 인증은 `x-goog-api-key` 헤더로 한다.
  - 검증된 제공자가 있으므로 PWA를 유지한다. 래핑 앱은 만들지 않는다. → **v0.18에서 변경**: 사용자 결정(2026-11-05)으로 Capacitor 앱으로 배포한다(2.1.2). Anthropic 호출은 앱 안에서도 WebView `fetch`와 같은 CORS 조건으로 한다.
- **휴대폰 안 AI(v0.20, 3.6.1)**: 제공자 호출이 아니라 OS가 제공하는 기기 안 모델이다. 엔드포인트와 열쇠가 없고, 본문과 결과는 기기 밖으로 나가지 않는다. 다만 Android ML Kit은 기기 정보, 앱 정보, 사용 횟수와 지연 시간, 입출력 크기 같은 **진단·사용 통계를 Google에 보낸다**(입력 글과 결과 글 자체는 포함하지 않는다고 안내됨, `developers.google.com/ml-kit/android-data-disclosure`). 이 전송은 앱 코드가 아니라 SDK가 하며 끌 수 없으므로 절대 규칙 2의 **예외**로 허용하고, 설정의 휴대폰 안 AI 카드에 알리고 Google 안내 링크를 둔다(사용자 결정 2026-11-06). 모델 내려받기는 OS(AICore)가 하며, 사용자가 "내려받기"를 누를 때만 시작한다.
- **Google Play 결제(v0.21, 3.17)**: Android 앱의 "커피 사 주기"는 Google Play Billing Library가 Google Play 앱과 통신해 처리한다. 앱 코드가 외부로 요청을 보내지 않고, 결제 정보는 Google Play 화면에서만 입력한다. 사용자가 버튼을 누를 때만 상품 조회와 결제가 일어나며, 이 통신은 절대 규칙 2의 **두 번째 예외**다(사용자 결정 2026-11-06). 서버가 없으므로 영수증 서버 검증은 하지 않는다. 기능을 여는 상품이 아니라 후원이므로 위조 결제의 피해가 없다.
- **한도 관리 불가**: 전역 일일 한도를 둘 수 없다. 기기별로 자가 한도(예: 하루 호출 횟수)를 두고, 실제 한도는 제공자 계정 기준으로 사용자가 관리한다.

### 3.1 본문 뷰어
- 역본 선택: 언어별 기본 역본(한국어 개역한글, 영어 KJV)이 자동으로 선택되고, **읽기 화면의 도구 막대**에서 바로 바꾼다(번들 역본과 "내가 가져온 역본"을 함께 보여준다, 3.12 참고). 책, 장, 절 단위 조회, 이전/다음 장 이동
- 읽기 화면 위쪽은 한 줄 도구 막대만 둔다: [현재 책·장 버튼] [역본 고르기] [검색]. 책·장 버튼을 누르면 책·장 고르기와 참조 직접 입력이 펼쳐지고, 이동하면 접힌다. 첫 화면에서 본문 첫 절이 스크롤 없이 보여야 한다(360×640 기준).
- 참조 입력창으로 직접 입력 가능(책·장 패널 안)
- 본문 선택은 롱터치로 시작한다(3.1.1).

#### 3.1.1 본문 선택 (모바일 롱터치)
**진입**
- 절을 약 450ms 길게 누르면 선택 모드가 켜지고 체크 표시가 나타난다. 지원 기기에서는 짧은 진동을 준다.
- 본문 영역에서 기본 롱프레스 동작(텍스트 선택 메뉴, 이미지 저장 메뉴)을 막는다.

**범위 확장**
- 선택은 여러 개의 연속 블록으로 유지한다(다중 블록).
- 선택 모드에서 기존 블록에 **인접한 절**(블록의 바로 앞 또는 바로 뒤 절)을 탭하면 그 블록이 확장된다.
- 인접하지 않은 절(**떨어진 절**)을 탭하면 기존 블록은 그대로 두고 새 블록이 추가된다.
- 이미 선택된 절을 탭하면 그 절만 해제된다. 블록 중간 절을 해제하면 블록이 둘로 나뉜다.
- 누른 채 위아래로 끌면 시작 절부터 현재 절까지 절 단위로 블록이 바뀐다. 자동 스크롤은 화면 가장자리에서만 동작한다.
- 선택 결과는 장 순서대로 정렬된 연속 블록 목록으로 정규화하고, 인접하거나 겹치는 블록은 합친다.
- 참조 문자열은 블록을 쉼표로 잇는다. 예: "요 15:1–8, 12", "요 15:1–3, 5–7". 참조 파서는 이 쉼표 목록 형식을 같은 규칙으로 해석한다.
- MVP의 선택 범위는 한 장 안으로 한정한다. 장을 이동하면 선택이 해제된다.

**액션 바**
- 선택이 1개 이상이면 하단에 액션 바가 뜬다. 가장 눈에 띄는 주 버튼은 **"말씀 나눔 초안"**이고, 그 아래에 복사, 말씀 구성표, 삶에 닿는 예시, 가벼운 한마디, 내 설교에서 찾기를 둔다.
- "말씀 나눔 초안": AI 연결이 있으면 생성 화면(3.7)을 연다. 연결이 없으면 요청 없이 안내 화면을 열어 "AI 연결하기"(설정의 연결 항목)와 "말씀 구성표로 쓰기"(3.4) 중에서 고르게 한다.
- 액션 바의 참조 문자열(예: "요 15:1–8")은 직접 입력과 같은 파서를 거친다.

**해제**
- "선택 해제", "전체 해제" 버튼, 빈 곳 탭으로 종료한다.

**접근성과 대체 수단**
- 각 절 왼쪽에 체크 영역을 둔다. 롱터치가 어려운 사용자도 체크로 선택할 수 있다.
- 선택 상태는 스크린리더에 "선택됨, 27절"로 읽히도록 한다.

**측정(로컬 집계, 외부 전송 없음)**
- 진입 성공률, 취소율, 직접 입력 우회율을 기기 안에서만 집계하고, 설정 화면에서 사용자에게 보여준다. 외부로 보내지 않는다.

### 3.2 구절 검색
- 키워드 검색: 선택한 역본 본문에 대해 `LIKE ? ESCAPE '\'`(부분 문자열 일치)로 찾는다. sql.js 1.15.2 기본 빌드에는 FTS5가 없고(FTS3만 있음), 3만 1천 절에서 LIKE 검색이 2~16ms(Node 실측, 2026-11-04)라 별도 색인을 두지 않는다. 검색어는 1~50자, `%`·`_`·`\`는 이스케이프하고, 결과는 50건씩 나눠 보여준다.
- 참조 검색: "요 15:1-8", "요한복음 15장 1절", "John 3:16" 형식을 파싱해 바로 이동

### 3.3 내 설교에서 찾기 (독립 모드)
- 선택한 구절과 키워드로 기기 안의 설교 청크를 점수화해서 상위 3개를 보여준다.
- 결과는 원고 원문 일부이므로, 화면에서만 보여주고 외부로 보내지 않는다(LLM 호출 시에는 4.4 규칙을 따른다).

### 3.4 말씀 구성표 (독립 모드)
- 고정 템플릿(제목, 도입, 본문 해설, 적용, 맺음 기도)에 본문 원문과 선택한 발췌를 채운다.
- 문장은 새로 생성하지 않는다. 사용자가 직접 편집할 빈칸을 둔다.
- 결과에 복제 검사(7.3)를 적용한다. 단, 구성표에 그대로 넣은 본문 인용 블록과 발췌 인용 블록은 검사 대상에서 제외하고, 사용자가 빈칸에 쓴 텍스트만 검사한다(인용 블록은 구분 표시한다).
- 저장하면 `outline` 스토어에 암호화해 보관한다(발췌 인용에 원고 원문이 들어가므로). 목록에서 다시 열어 고치거나 지울 수 있다. 제목·근거 참조·인용한 원고 id·생성일·수정일만 평문이다. 원고를 지우면 그 원고를 인용한 발췌 블록을 구성표에서 함께 지운다(같은 트랜잭션).

### 3.5 가벼운 한마디와 삶에 닿는 예시 라이브러리 (독립 모드)
- 사용자가 직접 추가하거나 편집하고, 구절 태그로 검색한다.
- 기본 콘텐츠를 넣을 경우 출처와 저작권 상태를 먼저 확인한다. MVP는 빈 상태로 출시하고, 빈 화면에 추가 방법을 안내한다.

### 3.6 LLM 연결 (사용자 API 키)
- 최초 연결은 설정 마법사(3.13)로 안내한다. 설정 화면에서는 같은 기능을 "연결 다시 하기"로 다시 열 수 있다.
- 대상 사용자는 컴퓨터와 LLM에 익숙하지 않을 수 있으므로, 용어는 "API 키" 대신 "연결 열쇠(API 키)"처럼 풀어 쓰고, 각 단계는 한 화면에 하나씩 보여준다.
- 제공자 선택: 설정에서 제공자와 모델을 고르고, 본인 API 키를 입력한다.
  - 고를 수 있는 모델 목록과 기본값은 `config/app.config.json`의 `providers.<id>.models`와 `model`에서 읽는다.
  - Anthropic 기본값은 `claude-haiku-5-5`로, 비용을 가장 적게 쓰는 선택이다. `claude-sonnet-5-5`와 `claude-opus-5-5`도 고를 수 있다.
  - 모델 이름 옆에는 "빠르고 저렴함", "균형", "가장 정교함"처럼 쉬운 말로 풀이를 붙인다. 요금 금액은 적지 않는다.
  - 모델은 나중에 설정에서 바꿀 수 있다.
- 키 검증: 저장 시 가벼운 요청으로 유효성을 확인하고 성공 여부만 표시한다.
- 키 삭제: 기기에서 즉시 삭제한다.
- 화면 안내: "API 키는 이 기기에만 암호화되어 저장됩니다. 요금은 제공자에게 직접 청구되며, 구독(ChatGPT Plus, Claude Pro 등)과 API 요금은 별도입니다."
- 키가 없으면 LLM 기능만 잠기고, 나머지 기능은 그대로 쓴다.

### 3.6.1 휴대폰 안 AI (v0.20, S15)
- **언제 쓰나**: 연결된 제공자(열쇠)가 없고, 사용자가 설정에서 휴대폰 안 AI를 켰고, OS가 "준비됨"(available)을 알릴 때만 쓴다. 열쇠가 연결되어 있으면 연결된 제공자를 먼저 쓴다.
- **플랫폼**:
  - Android: ML Kit GenAI Prompt API `com.google.mlkit:genai-prompt:1.0.0-beta4`(AICore의 Gemini Nano). minSdk 26. 앱이 화면 맨 앞에 있을 때만 동작하고, 앱별 한도(BUSY, 배터리 한도)가 있다. 지원 기기 목록에 없는 기기도 OS가 "내려받을 수 있음"을 알리면 쓸 수 있다(Galaxy S25 실기기 확인 2026-11-06).
  - iOS: Apple Foundation Models(iOS 26 이상, Apple Intelligence 지원 기기와 지역). 플러그인은 맥에서 빌드해야 하므로 후속으로 둔다.
- **범위**: 삶에 닿는 예시(2개)와 가벼운 한마디(2개)만 만든다(`on_device_ai.kinds`). 문맥 창이 작아서(입력과 출력 합쳐 약 4,000토큰) 말씀 나눔 초안은 만들지 않는다. 초안을 열면 "연결 없음" 안내에 "휴대폰 안 AI는 짧은 결과만 만든다"는 줄을 더한다.
- **프롬프트**: `src/prompts/<lang>/device.json`의 짧은 지시(150단어 이하)와 본문, 핵심어, 할 일, 출력 형식만 넣는다. 페르소나, 스타일 프로필, 내 설교 발췌는 넣지 않는다. 본문 글자 수가 `on_device_ai.max_passage_chars`를 넘으면 호출하지 않고 "구절을 줄여 달라"는 안내를 띄운다. 출력 토큰 상한은 `on_device_ai.max_output_tokens`.
- **검증**: 같은 규칙을 해당 부분에 적용한다(구조와 개수, 근거 절 범위, 금지 표현과 실존 인물, 복제 검사, 가벼운 한마디 기준). 가벼운 한마디는 기준에 맞지 않는 것만 빼고, 하나도 남지 않으면 실패다. 재시도 1회, 다시 실패하면 독립 결과.
- **일일 한도와 캐시**: 외부 호출과 요금이 없으므로 기기별 일일 한도(`local_limits`)에 세지 않는다. 결과를 캐시하지 않는다.
- **실패 원인**: 바쁨·한도·앱이 뒤에 있음 → "앱을 켜 둔 채 잠시 뒤 다시", 준비 안 됨·저장 공간 → "설정에서 상태 확인", 너무 김 → "구절을 줄여 달라". 그 밖은 원인 불명 문구.
- **설정 카드**: 상태(확인 중, 준비됨, 내려받을 수 있음, 내려받는 중, 쓸 수 없음), "내려받기"(누를 때만), "켜기/끄기"(기본 꺼짐), "연결된 AI를 먼저 쓴다" 안내, Android는 ML Kit 진단 정보 안내와 Google 안내 링크. 브라우저 빌드에는 카드가 없다.

### 3.7 말씀 나눔 초안, 삶에 닿는 예시 (LLM 사용)
- **말씀 나눔 초안**: 페르소나, 스타일 프로필, 참고 발췌, 본문, 키워드를 조합해 약 1000자 초안을 만든다. 구성은 제목, 도입, 본문 해설, 적용 2~3가지, 맺음 기도.
- **삶에 닿는 예시**: 본문을 참조하는 예시 2개를 만들고, 각 예시에 근거 절 번호를 붙인다.
- **가벼운 한마디**: 본문 메시지를 강화하는 한마디 2개를 만들고, 검증(7.3)을 통과한 것만 보여준다.
- 결과 화면에는 "AI가 만든 초안입니다. 고쳐 쓰시면 더 좋아요."를 표시한다.
- 실패하면 독립 모드 결과(말씀 구성표, 라이브러리)를 함께 보여준다.

### 3.8 페르소나 설정
- 선택지로만 입력받는다: 교단 전통(장로교, 감리교, 침례교, 성결·오순절, 초교파/기타), 강조점(복수: 은혜, 언약, 실천, 선교, 성령, 말씀 묵상, 공동체), 설교 방식(강해식, 주제식, 이야기식), 말투(권면형, 설명형, 간결 단호형), 대상(개인, 소그룹, 청년, 장년), 길이(MVP는 1000자 하나로 고정).
- 길이는 말씀 나눔 초안 본문의 글자 수다. 공백을 포함한 그래핌(사용자가 보는 글자) 수로 세고, 초안에 덧붙이는 삶에 닿는 예시와 가벼운 한마디는 포함하지 않는다(영어는 `i18n.english_length_words`의 단어 수).
- 여러 페르소나를 구분하는 이름은 20자 이내 라벨이다. 프롬프트에 넣지 않고, 실존 인물 패턴("○○ 목사", "○○○ 목사님 스타일" 등)이면 거부한다(자유 입력 금지 규칙의 유일한 예외).
- 실존 목회자 이름은 입력받지 않는다.
- 교단은 "전통 경향"으로만 반영하고, 교리 단정 표현은 프롬프트에서 금지한다.
- 여러 개를 저장하고 골라 쓸 수 있다.

### 3.9 설교 원고 업로드와 스타일 프로필
- **업로드**: txt, docx, 텍스트 PDF, 직접 붙여넣기. 이미지 기반 PDF는 MVP에서 제외한다.
- **동의**: "본인이 작성했거나 이용 권한이 있는 설교문"이라는 체크를 필수로 받고, 동의 시각을 기록한다.
- **처리 위치**: 파싱, 마스킹, 청크 분할 모두 기기 안에서 한다.
- **마스킹**: 패턴으로 다음만 가린 뒤 저장한다. 전화번호(휴대·유선) → `[연락처]`, 이메일 → `[연락처]`, 주소(시·도/구·군/동·로·길 + 번지) → `[주소]`, "○○교회" → `[교회]`, 직분 호칭이 붙은 이름("○○○ 집사/권사/장로/성도/목사/전도사", 뒤에 "님" 허용) → `[이름] 집사`처럼 호칭은 남긴다. 호칭 없는 이름은 가리지 않는다(바울, 다윗 같은 성경 인명 오탐 방지). 저장 전 미리보기에서 사용자가 구간을 골라 추가로 가릴 수 있다(`[가림]`으로 바뀐다). 미리보기에서 고친 글은 저장할 때 같은 패턴으로 한 번 더 가린다. 마스킹 전 원문은 메모리에서만 쓰고 저장하지 않는다.
- **파싱**: txt는 UTF-8(`TextDecoder` fatal), docx는 fflate로 압축을 풀고 브라우저 XML 파서로 `word/document.xml`의 문단 텍스트를 뽑는다, 텍스트 PDF는 pdf.js(pdfjs-dist)로 텍스트 레이어를 뽑는다. pdf.js 워커와 한국어 CMap은 앱과 같은 출처 파일로 번들하고, 두 라이브러리 모두 업로드 화면에서만 지연 로딩한다. eval을 쓰는 라이브러리(예: 템플릿에 `new Function`을 쓰는 mammoth)는 CSP 때문에 쓰지 않는다.
- **이미지 PDF 판정**: 공백을 뺀 추출 글자 수가 페이지당 평균 30자(`sermon_ingest.image_pdf_min_chars_per_page`) 미만이면 "이미지로 된 PDF는 아직 지원하지 않습니다"로 거부한다.
- **저장**: 원문과 청크는 암호화해서 IndexedDB에 저장한다. 메타데이터(제목, 해시, 생성일)만 평문으로 둔다.
- **스타일 프로필**: LLM 연결이 있을 때만 만든다. 원고 전체를 제공자에게 보내야 하므로, 전송 전에 "원고가 선택한 AI 제공자로 전송됩니다"를 확인받는다. 결과는 문장 길이 평균, 질문형 비율, 예화 빈도, 구성 방식, 말투 요약(3줄 이내), 자주 쓰는 표현(최대 10개)으로 구성하며 원문 문장은 넣지 않는다. 문장 길이 평균과 질문형 비율은 기기에서 계산하고, 나머지는 모델이 답한다. 보내는 원고는 가린 본문이며 전체 `generation.style_profile_max_input_chars`(40,000자)를 원고 수로 나눈 만큼 앞부분만 보낸다. 원고가 바뀌면(`source_hash` 불일치) 프로필은 초안 프롬프트에 넣지 않고 "다시 만들기"를 안내한다. 초안 프롬프트에는 `external_transfer` 동의가 있을 때만 넣는다.
- **원고 수**: 3편 미만이면 "스타일 반영이 제한적입니다"를 안내한다.
- **재생성**: 설교를 추가하거나 삭제하면 `source_hash`가 바뀌어 프로필을 무효화한다. MVP에는 저장한 원고를 고치는 기능이 없다(고치려면 지우고 다시 올린다).
- **삭제**: 설교를 삭제하면 원문, 청크, 관련 프로필을 기기에서 즉시 삭제한다.

### 3.11 로컬 백업
- 서버가 없으므로 기기를 바꾸거나 앱을 지우면 데이터가 사라진다. 이를 막기 위해 백업 파일을 내보내고 가져올 수 있게 한다.
- 백업 파일은 사용자가 정한 암호(PBKDF2-SHA256 600,000회로 키 파생, AES-GCM 암호화)로 보호한다. 암호는 8자 이상이고 두 번 입력해 일치해야 한다. 암호와 파생 키는 메모리에서만 쓰고 저장하지 않는다.
- 암호 분실 안내는 내보내기 화면에 항상 표시하고, 사용자가 확인 체크를 해야 내보낼 수 있다. 문구: "이 암호를 잊으면 백업 파일을 열 수 없고, 누구도(앱 제작자도) 복구해 드릴 수 없습니다. 암호를 종이에 적어 안전한 곳에 보관하세요." (영어: "If you forget this password, the backup file cannot be opened, and no one — not even the app's makers — can recover it. Write the password on paper and keep it somewhere safe.")
- 백업 내용: 원고와 청크, 페르소나와 사용 중인 페르소나(`settings.persona_id`), 라이브러리, 말씀 구성표(`outline`), 스타일 프로필, 언어·역본 설정. 말씀 구성표의 발췌 인용은 그 원고가 함께 복원되지 않아도 그대로 두고, 원고를 삭제할 때만 지운다. API 키는 기본적으로 제외한다(기기별 키 묶음이므로). 포함하려면 별도 확인을 거친다.
- 백업 파일 전송(메일, 클라우드 파일 앱 등)은 사용자가 직접 하며, 앱은 외부로 보내지 않는다.

### 3.12 언어와 역본 설정

**UI 언어**
- 지원 언어: 한국어(`ko`), English(`en`). 첫 실행 시 기기 언어를 기본값으로 추천하고, 설정에서 바꿀 수 있다.
- 언어를 바꾸면 화면 문구, 노출 이름(3.0), 페르소나 선택지 표시가 즉시 바뀐다. 사용자 데이터는 그대로 둔다.
- 화면 문구는 언어 리소스 파일(`ko.json`, `en.json`)에서만 관리한다. 컴포넌트에 문자열을 직접 쓰지 않는다.

**기본 역본**

| UI 언어 | 기본 역본 | 저작권 상태 |
|---|---|---|
| 한국어 | 개역한글(krv) | 공공 도메인 |
| English | KJV(kjv) | 퍼블릭 도메인 |

- UI 언어와 역본은 독립적으로 고를 수 있다. 예: 한국어 화면에서 KJV 본문 읽기.
- 읽기 화면에서 역본을 바꾸면 그 역본이 이후 기본값이 된다. 설정 화면에는 역본 관리(가져오기, 삭제, 안내)만 둔다.

**영어 역본 옵션**

| 역본 | 상태 | 처리 방침 |
|---|---|---|
| KJV | 기본값 | 퍼블릭 도메인. crizin/bible-db에 포함된 것으로 확인됨(README 기준, 배포 전 재확인) |
| WEB | 후보 | 퍼블릭 도메인. 현대 영어 대안. 데이터 확보 경로는 구현 단계에서 확인 |
| NIV | 제외 | Biblica 저작권. 번들과 배포에 라이선스가 필요하므로 기본값에 넣지 않는다. 라이선스를 받은 뒤 옵션으로만 검토 |

**생성 결과의 언어**
- 말씀 나눔 초안, 삶에 닿는 예시, 가벼운 한마디의 언어는 UI 언어를 따른다.
- 본문이 KJV이고 UI가 한국어이면, 설명은 한국어로 쓰고 인용 구절은 KJV 원문 그대로 표시한다.
- 프롬프트의 시스템 지시문은 UI 언어에 맞춰 `prompts/`에서 두 벌로 관리한다.

**검증**
- 영어 출력에도 3장의 검증(근거 절 범위, 길이, 금지 표현, 복제 검사)을 동일하게 적용한다. 길이 기준은 영어에서 단어 수로 환산해 `config`에 따로 둔다.

### 3.13 설정 마법사와 API 키 발급 안내

**대상과 원칙**
- 컴퓨터와 LLM에 익숙하지 않은 목회자를 기본 사용자로 본다.
- 한 화면에 한 가지 행동만 요구한다. 전문 용어는 처음 나올 때 한 줄로 풀어 쓴다.
- 마법사는 건너뛸 수 있다. 건너뛰어도 독립 모드 기능은 모두 쓸 수 있고, 설정 화면에서 언제든 다시 열 수 있다.
- 제공자 안내 문구와 스크린샷은 릴리스마다 점검한다. 화면 이름이 바뀌면 안내를 고친다.

**마법사 단계**

| 단계 | 화면 목적 | 주요 내용 |
|---|---|---|
| 1. 언어 | UI 언어 선택 | 한국어 / English, 기기 언어를 기본 선택 |
| 2. 본문 | 기본 역본 확인 | 한국어는 개역한글, 영어는 KJV 안내 |
| 3. 사용 방식 | LLM 사용 여부 선택 | "지금은 건너뛰기(앱의 기본 기능만 사용)" 또는 "AI 기능도 사용하기". 어댑터(S08) 전에는 "AI 기능도 사용하기"를 누르면 "준비 중" 안내 후 홈으로 간다(마법사 상태는 `skipped`). S08 이후 검증된 제공자(`browser_direct_verified: true`)가 0개면 이 선택지를 숨긴다 |
| 4. 제공자 선택 | 제공자 고르기 | 비교 카드 3개(아래 표). 고를 수 있는 것은 `browser_direct_verified: true`인 제공자뿐이다(현재 Gemini, Anthropic. v0.19). Gemini가 미리 골라져 있고 추천 표시가 붙는다. OpenAI는 "이 업체는 앱에서 바로 호출하는 방식을 제공하지 않습니다" 안내 카드로 보여주고 누를 수 없다. 추천 표시는 검증된 제공자에만 붙인다(`wizard.beginner_recommendation`) |
| 5. 발급 안내 | 선택한 제공자의 발급 절차 | 번호 매긴 체크리스트, 각 단계 완료 체크, 외부 사이트는 사용자가 누를 때만 열림 |
| 6. 키 붙여넣기 | 키 입력 | 붙여넣기 전용 입력칸, 형식 힌트(접두사) 표시, 입력 후 마스킹 |
| 7. 확인 | 키 검증 | 짧은 요청 한 번으로 확인. 성공 또는 실패 원인별 안내(3.13.3) |
| 8. 원고 전송 동의 | 전송 범위 설명 | 원고 전송 여부를 별도 체크로 선택. 기본값은 "보내지 않음" |
| 9. 완료 | 다음 행동 안내 | "백업 파일 만들기 권장", 독립 기능 바로가기 |

**제공자 비교 카드 (4단계)**

| 항목 | Gemini (Google) | OpenAI | Anthropic (Claude) |
|---|---|---|---|
| 시작 비용 | 무료 티어 있음, 결제 없이 시작 가능 | 결제 수단 등록과 크레딧 충전 필요 | 결제 수단 등록과 크레딧 구매 필요 |
| 입력 데이터 사용 | 무료 티어 입력은 Google 제품 개선에 쓰일 수 있음 | 유료 API 기준 별도 정책 확인 필요 | 제공자 정책 확인 필요 |
| 구독과의 관계 | 해당 없음 | ChatGPT 구독과 API 요금은 별도 | Claude 구독과 API 요금은 별도 |
| 키 접두사(형식 힌트) | `AIza` | `sk-` | `sk-ant-` |
| 추천 대상 | 처음 써 보는 사용자 | 결제에 익숙한 사용자 | 결제에 익숙한 사용자 |
| 현재 상태(2026-11-06) | 선택 가능, 추천(v0.19) | 비활성: 앱에서 바로 호출하는 방식 미제공 | 선택 가능 |

- 비활성 카드는 선택 버튼이 없다. 사유(`unavailable_reason`: `pending_verification` 또는 `no_browser_access`)는 config에서 읽는다.
- Gemini는 v0.19에서 활성화했다(PROVIDERS.md 확인 날짜 2026-11-06). 모델은 `gemini-flash-latest`(기본), `gemini-flash-lite-latest`다.

- 비용 금액은 안내 문구에 고정해 쓰지 않는다. "요금은 바뀔 수 있으니 제공자 요금 페이지를 확인하세요"라고 안내하고, 사용자가 확인하도록 링크를 둔다.
- 입력 데이터 사용 항목은 Gemini 무료 티어를 선택했을 때 반드시 표시한다.

**3.13.1 제공자별 발급 안내 (5단계 내용)**

*Gemini* (사용자 제공 안내 메모 대조 2026-11-06, `docs/guides/gemini-api-key.md`, v0.19)
1. Google AI Studio(aistudio.google.com)에 들어가 평소 쓰는 Google 계정으로 로그인한다. 비밀번호는 Google 화면에만 입력한다.
2. "Get API key"(API 키 가져오기)를 누른다.
3. "Create API key"(API 키 만들기)를 누른다. 프로젝트를 고르라고 나오면, 처음이면 "Create API key in new project"(새 프로젝트에서 만들기)를 고른다.
4. 만들어진 키를 복사한다. `AIza`로 시작한다.
5. 앱으로 돌아와 붙여넣는다.
- 주의: 무료로 쓸 때는 보낸 내용이 Google 서비스 개선에 쓰이거나 사람이 검토할 수 있다. 민감한 내용은 보내지 않는다. 결제 계정으로 바꾸면 학습에 쓰이지 않는다. 무료 사용에는 횟수 제한이 있다(수치는 적지 않는다).
- 생성 전 전송 안내에도 같은 주의를 표시한다(`generate.notice_gemini`).

*OpenAI*
1. platform.openai.com에서 가입하거나 로그인한다. ChatGPT 웹사이트 계정과 같은 화면이 아니다.
2. 결제(Billing) 메뉴에서 결제 수단을 등록하고 크레딧을 충전한다.
3. API keys 메뉴에서 "Create new secret key"(새 비밀 키 만들기)를 누른다.
4. 키를 복사한다. `sk-`로 시작하며 한 번만 보여준다.
5. 앱으로 돌아와 붙여넣는다.
- 주의: ChatGPT 구독(Plus 등)과 API 요금은 별도입니다. 지출 한도 설정 메뉴가 있으면 한도를 정해 두세요.

*Anthropic (Claude)* (공식 화면 대조 2026-11-05, `docs/PROVIDERS.md`)
1. Claude Console(platform.claude.com)에서 가입하거나 로그인한다.
2. 결제(Billing, `platform.claude.com/settings/billing`) 메뉴에서 결제 수단을 등록하고 크레딧을 구매한다.
3. API keys 메뉴(`platform.claude.com/settings/keys`)에서 "Create key"(키 만들기)를 누른다.
4. 만드는 창에서 다음을 정한다.
   - 키 이름: 알아보기 쉽게 정한다(예: "말씀 앱").
   - 만료 기간: 너무 짧으면 키가 금방 멈춘다. 오래 쓰려면 긴 기간이나 "Never"(만료 없음)를 고른다.
   - Linked account: 본인으로 둔다.
   - 작업공간(workspace): 기본 작업공간을 고른다. 작업공간을 고르지 않은 키는 이 앱에서 쓸 수 없다.
5. 키를 복사한다. `sk-ant-`로 시작하며 한 번만 보여준다.
6. 앱으로 돌아와 붙여넣는다.
- 주의: Claude 구독(Pro, Max 등)과 API 요금은 별도입니다. 회사·기관 계정에서 데이터 보존 제한(ZDR) 같은 설정이 켜져 있으면 앱에서 바로 호출할 수 없습니다.

*OpenAI*: 현재 비활성이라 발급 안내를 보여주지 않는다. 위 OpenAI 문구는 활성화할 때 공식 화면과 다시 대조한 뒤 쓴다.

**모든 제공자 공통 안내**
- 키는 다른 사람에게 보내지 않는다. 화면을 캡처해서 공유하지 않는다.
- 키가 노출되었다고 생각되면 제공자 사이트에서 즉시 삭제하고 새로 만든 뒤, 앱 설정에서 교체한다.
- 외부 사이트 링크는 사용자가 직접 누를 때만 브라우저에서 열린다. 앱이 미리 요청하지 않는다.

**3.13.2 키 검증**
- 검증은 사용자가 "확인" 버튼을 누를 때만 한 번 수행한다. 자동 반복 호출을 하지 않는다.
- 검증 요청은 가장 짧은 요청으로 하고, 응답 내용은 저장하지 않는다.
- 검증 호출도 기기별 일일 한도(`local_limits.daily_llm_calls_per_device`)에 1회로 센다. 한도에 닿으면 호출하지 않고 안내한다.
- 검증이 실패하면 원인별 안내와 함께 "다시 붙여넣기"와 "지금은 AI 없이 쓰기" 두 버튼을 보여준다. 실패한 키는 저장하지 않는다. "지금은 AI 없이 쓰기"를 누르면 마법사를 건너뛴 것과 같다. 독립 기능으로 홈에 가고, 설정의 "연결 다시 하기"로 다시 시작할 수 있다.
- 키 형식(접두사)이 다르면 제공자 호출 전에 "키를 다시 확인하세요. 이 칸은 Gemini 키 형식(AIza로 시작)입니다" 같은 안내를 띄운다. 형식 검사는 참고용이며, 최종 판단은 제공자 응답으로 한다.

**3.13.3 실패 원인별 안내**

| 원인 | 안내 문구 (요지) | 다음 행동 |
|---|---|---|
| 키 형식 오류 | 붙여넣은 내용이 키 형식과 다릅니다 | 다시 복사해서 붙여넣기 |
| 인증 실패 | 키가 올바르지 않거나 삭제되었습니다 | 제공자 사이트에서 새 키 만들기 |
| 결제 또는 크레딧 필요 | 결제 정보나 크레딧이 필요합니다 | 제공자의 결제 메뉴 확인 |
| 사용 한도 초과 | 오늘 사용 한도를 넘었습니다 | 내일 다시 시도하거나 한도 확인 |
| 지역 제한 | 이 지역에서는 제공되지 않습니다 | 다른 제공자 선택 |
| 네트워크 오류 | 인터넷 연결을 확인하세요 | 다시 시도, 독립 기능은 계속 사용 가능 |
| 작업공간 미지정 키 (Anthropic) | 이 키는 작업공간이 정해지지 않았습니다 | 키를 만들 때 기본 작업공간을 골라 다시 만들기 |
| 조직이 브라우저 호출을 막음 (Anthropic) | 이 계정은 설정 때문에 앱에서 바로 쓸 수 없습니다 | 개인 계정으로 키 만들기 또는 AI 기능 없이 사용 |

- 제공자별 HTTP 상태와 오류 코드 매핑은 `docs/PROVIDERS.md`를 따른다.
- 표에 없는 경우는 다음과 같이 안내한다.
  - 타임아웃(60초): 네트워크 오류 문구
  - 응답 형식 오류와 그 밖의 알 수 없는 원인: "연결에 실패했습니다. 키를 다시 확인해 주세요"(원인을 추측하지 않는다)

**3.13.4 원고 전송 동의**
- 원고는 기본적으로 보내지 않는다. 스타일 프로필을 만들 때 "원고를 선택한 AI 제공자에게 보내 말투를 분석합니다"라는 별도 동의를 받는다.
- 동의를 거절해도 원고 저장, 검색, 구성표 기능은 그대로 쓴다.
- Gemini 무료 티어를 쓰는 경우, 원고 전송 동의 화면에 "무료 사용 시 입력 내용이 제품 개선에 쓰일 수 있습니다"를 함께 표시한다.

**3.13.5 마법사 이후**
- 완료 화면에서 백업 파일을 만들도록 권한다. 백업 암호를 잊으면 복구할 수 없음을 함께 안내한다.
- 설정 화면에서 "연결 다시 하기", "키 삭제", "제공자 바꾸기"를 제공한다.

### 3.14 txt 역본 가져오기

**원칙**
- 앱은 권리 있는 본문을 포함하거나 배포하지 않는다. 사용자가 본인이 합법적으로 가진 txt 파일만 가져올 수 있다.
- 가져온 역본은 그 기기에만 저장된다. 앱 밖으로 공유하는 기능은 두지 않는다(백업 포함 여부는 아래 참고).
- txt 외 형식(docx, pdf, epub, 웹 페이지 저장본)은 받지 않는다. 안내 화면에서 txt로 저장하는 방법을 쉬운 말로 안내한다.

**허용 형식**
- 형식 A(권장): 한 줄에 한 절. `책이름 장:절 본문`
  - 예: `요한복음 3:16 하나님이 세상을 이처럼 사랑하사 ...`
  - 책 이름은 정식 이름, 약어, 영문 약어를 모두 인식한다(`bible-reference-parser`와 같은 규칙).
- 형식 B: 장 제목 줄 뒤에 절 줄이 이어지는 방식
  - 예: `요한복음 3장` 다음 줄부터 `16 하나님이 세상을 ...`
- 한 파일 안에서 형식 A와 B가 섞이면 거부한다.
- 인코딩: UTF-8을 먼저 시도하고, 실패하면 한국어 Windows 기본 인코딩(euc-kr 계열)을 시도한다. 어느 쪽으로 읽었는지 미리보기에 표시한다.
- 줄바꿈: LF와 CRLF 모두 허용. 빈 줄은 무시한다.
- 최대 크기: 10MB. 성경 전체 본문 기준으로 충분한 크기다.

**가져오기 절차 (5단계, 목회자 기준 쉬운 말로 안내)**
1. 파일 고르기: txt 파일만 선택 가능. 샘플 양식 받기(앱이 만든 빈 양식, 외부 파일 아님)로 형식을 미리 볼 수 있다.
2. 역본 정보 입력: 이름(예: "내 번역본 2024"), UI 언어, 메모.
3. 권리 확인: "이 파일은 제가 소유하거나 이용 허락을 받은 본문입니다"에 체크해야 다음으로 넘어간다. 체크 시각을 기록한다.
4. 검사와 미리보기: 인식된 책 수, 절 수, 누락된 장과 절, 중복 절, 인식하지 못한 책 이름을 보여준다. 66권이 모두 없어도 저장은 가능하며, 부분 역본으로 표시한다.
5. 저장: 확인을 누르면 IndexedDB에 저장한다. 실패하면 원인을 보여주고 파일은 그대로 둔다.

**검사 규칙**
- 절 번호가 장의 범위를 벗어나면 해당 줄을 경고 목록에 넣는다.
- 같은 책, 장, 절이 두 번 나오면 첫 번째만 쓰고 나머지는 경고로 표시한다.
- 경고가 전체의 20%를 넘으면 저장을 막고 형식을 다시 확인하게 한다.

**저장과 사용**
- 저장 형식: 책, 장, 절, 본문 텍스트. 성경 본문은 개인 데이터가 아니므로 암호화하지 않는다. 대신 배포 금지 표시를 둔다.
- 역본 선택 목록에 "내가 가져온 역본"으로 표시한다.
- 검색은 전수 검색이다. 검색 속도를 측정하고, 5초를 넘으면 인덱스 추가를 검토한다.
- 가져온 역본을 LLM에 보낼 때는 3.9의 외부 전송 동의와 같은 체계를 따른다.
- 생성 결과에 가져온 역본의 본문이 절 단위로 재인용되지 않도록 프롬프트에서 지시하고, 복제 검사(7.3)를 이 본문에도 적용한다.
- 구현(S11): 가져온 역본 id는 `imp-` 접두사로 번들 역본과 겹치지 않는다. 읽기 화면은 역본 전체를 IndexedDB에서 한 번 읽어 메모리에서 조회·검색한다(31,680절 합성 본문 기준 읽기 15ms, 전수 검색 1ms). 부분 역본에서 이전·다음 장은 있는 장으로 건너뛰고, 없는 장은 "이 역본에는 이 장이 없습니다"로 안내한다.
- 구현(S11): 가져온 역본을 읽는 중에도 말씀 구성표 인용, 내 설교에서 찾기 키워드, AI 요청 본문은 언어 기본 번들 역본(규칙 15)을 쓴다. 가져온 역본의 본문과 이름은 보내지 않는다. 프롬프트에는 재인용 금지 한 줄(`prompt.json` `no_requote`)만 더하고, 해당 구절의 가져온 본문을 복제 검사 원천에 넣는다. 요청 전 안내에 이 사실을 한 줄로 보여준다.
- 구현(S11): `#`으로 시작하는 줄은 주석으로 읽지 않는다(빈 샘플 양식은 0절). 장·절 범위 기준은 번들 krv·kjv 중 큰 값이다. 형식 B 장 제목은 `장`·`편` 접미사를 허용한다. 저장 시 `consent_log(bible_rights)`를 같은 트랜잭션에 기록한다. 선택 중인 역본을 지우면 언어 기본 역본으로 돌아간다.

**삭제와 백업**
- 역본 단위로 삭제할 수 있다. 삭제 시 해당 역본의 모든 절을 제거한다.
- 백업 파일에는 기본적으로 포함하지 않는다. 용량이 크고, 권리 상태를 앱이 보장할 수 없기 때문이다. 백업 화면에 "가져온 역본도 포함" 선택을 두되 기본은 꺼짐이다. 켜면 "본인이 소유하거나 이용 허락을 받은 본문만 포함됩니다. 백업 파일을 다른 사람에게 주지 마세요" 확인을 한 번 더 받고 `consent_log(backup_include_bible)`에 기록한다.
- 인코딩 인식 기준: 앱이 만든 합성 본문(실제 번역 아님)을 euc-kr로 저장한 픽스처가 UTF-8판과 같은 검사 결과를 내면 합격이다. 한국어 Windows 메모장에서 저장한 실제 파일은 수동 검증으로 확인한다.

### 3.15 역본 안내 링크 (읽기와 내려받기)

**원칙**
- 역본별로 두 가지 링크를 둔다. (1) 공식 열람처(읽기 전용, 모든 역본), (2) 내려받기 링크(퍼블릭 도메인으로 확인된 txt 파일만).
- 내려받기 링크는 `config/bible-sources.json`에서만 관리하고, 확인 날짜를 함께 둔다.
- 링크는 사용자가 누를 때만 브라우저에서 열린다. 앱이 미리 요청하지 않는다.
- 저작권이 있는 역본은 txt 내려받기 링크를 두지 않는다. 과거에 파일을 올린 블로그 글도 현재는 열람처 링크로 바꾸고 파일 배포를 중단한 사례가 있다(근거: 2026-10-02 확인, faithjikimi.tistory.com/604). 이 원칙을 따른다.

| NIV, NASB, NKJV | 저작권 있음 | BibleGateway | 없음 |
| Webster | 확인 필요 | 확인 필요 | 후보(blessedtxts 등). 출처 검증 후 등록 |

- Project Gutenberg 표기는 미국 기준 퍼블릭 도메인이다. 다른 나라에서는 상황이 다를 수 있으므로, 앱 안내에 "미국 기준" 문구를 함께 둔다.
- 현대인의성경, 현대어성경, 국한문 개역한글 등 확인되지 않은 역본은 링크를 비워 둔다.
- 내려받기 등록 범위(2026-11-05 확정): KJV와 WEB은 공식 페이지를 직접 열어 퍼블릭 도메인 표기와 txt 제공을 확인한 경우에만 확인 날짜와 함께 등록한다. Webster는 공식 출처가 없어 읽기·내려받기 링크를 모두 비워 둔다.

- 레지스트리 구현(S11): `config/bible-sources.json` 항목의 화면 이름은 i18n `bible_guide.name.<id>`, `note`는 i18n `bible_guide.note.<키>`를 가리킨다. `check-config.mjs`가 스키마, https 링크, `download_url`의 퍼블릭 도메인·확인 날짜 조건, `read_url`의 확인 날짜, `unverified` 항목 링크 금지, i18n 키 존재를 검사한다.

**화면 규칙**
- 역본 안내 화면에서 각 역본의 "읽기", "내려받기" 버튼을 보여준다. "내려받기"는 퍼블릭 도메인이며 링크가 검증된 역본에만 나온다.

### 3.16 글자 크기 조정

- 기본 글자 크기는 16px이다. 크기 단위는 CSS px로 쓴다(터치 타깃 44×44px 포함).
- 설정 화면에서 글자 크기를 단계로 고른다: 기본(16px), 크게(18px), 더 크게(20px), 아주 크게(22px). 단계 값은 `config`의 `ui.font_size_px.options`에서 읽는다. 기본보다 작게 줄이는 단계는 두지 않는다.
- 고르는 즉시 앱 전체(본문 뷰어, 마법사, 결과 패널 포함)에 반영한다. 글자 크기는 모두 `rem`으로 쓰고 루트 글자 크기만 바꾼다.

- 가장 큰 단계에서도 360px 화면에서 가로 스크롤이 없어야 하고, 터치 타깃은 44×44px 이상을 유지한다.
- 미리보기 문장을 함께 보여줘 크기를 확인하고 고를 수 있게 한다.

## 4. 데이터 저장과 보안

### 4.1 저장소 구성 (IndexedDB)

| 스토어 | 주요 필드 | 암호화 |
|---|---|---|
| `persona` | id, name, denomination, emphasis, style, tone, audience, length | 평문 (선택값만) |
| `settings` | key, value (UI 언어, 현재 역본, 역본 직접 선택 여부, 마법사 완료 여부, 외부 전송 안내 설정 `transfer_notice`, 글자 크기, 연결한 제공자 id `llm_provider`, 모델 `llm_model`) | 평문 (키·원고 금지) |
| `consent_log` | id, kind(sermon_rights / external_transfer / bible_rights / backup_include_key / backup_include_bible), target_id, granted, at | 평문 |
| `sermon_meta` | id, title, source_hash, consent_at, created_at | 평문 (메타데이터) |
| `sermon_body` | sermon_id, ciphertext, iv | 암호화 |
| `sermon_chunk` | id, sermon_id, seq, ciphertext, iv, keywords, verse_refs | 본문만 암호화. keywords·verse_refs는 점수화 속도를 위해 평문이며 단어와 참조만 넣고 문장은 넣지 않는다 |
| `style_profile` | id(`current` 하나), profile_json(원고 삭제 후 null), source_hash(원고 `source_hash`를 정렬해 이은 값의 SHA-256), prompt_version, sermon_count, created_at | 평문 (원문 없음) |
| `library_item` | id, kind(example / one_liner), body, verse_refs, tags, created_at | 평문 (사용자 작성 콘텐츠이므로 필요 시 암호화 옵션) |
| `outline` | id, title, ref, excerpt_sermon_ids, created_at, updated_at, ciphertext, iv | 섹션·블록 본문 암호화 (3.4) |
| `gen_cache` | key(프롬프트 버전·제공자·모델·프롬프트의 SHA-256), ciphertext, iv, prompt_version, provider, model, created_at. 최근 50개만 유지 | 결과 본문 암호화 |
| `provider_key` | provider, key_ciphertext, iv, key_last4, created_at | 암호화 |
| `crypto_key` | id, cryptoKey (non-extractable) | 키 자체는 추출 불가 |
| `local_stats` | 날짜, 호출 횟수(`llm_calls`, 키 검증 포함), 롱터치 집계 | 평문 (외부 전송 없음) |
| `imported_bible` | id, name, language, encoding, verse_count, partial, rights_consent_at, no_redistribute, created_at | 평문 (3.14) |
| `imported_verse` | bible_id, book, chapter, verse, text (키 `[bible_id, book, chapter, verse]`, 색인 `by_bible`, DB v7) | 평문 (3.14, 개인 데이터 아님) |

- 본문 DB(`bible.sqlite`)는 IndexedDB가 아니라 번들 파일로 두고, 읽기 전용으로 연다.
- **버전 관리**: IndexedDB 데이터베이스는 `open_sermon` 하나다. `core/store`의 `MIGRATIONS` 배열에서 `MIGRATIONS[i]`는 버전 i를 i+1로 올리는 함수이고, DB 버전은 배열 길이다. 스토어를 추가하는 단계는 배열 끝에 항목을 덧붙이기만 하고 기존 항목은 고치지 않는다. 업그레이드 뒤 기존 값이 남아 있는지 테스트한다. 래퍼는 라이브러리 없이 직접 구현한다(Promise 래퍼, 테스트는 fake-indexeddb).
- 원고 삭제는 소프트 삭제(표시만 남기기)를 하지 않는다. `sermon_meta`, `sermon_body`, `sermon_chunk`, 무효화된 `style_profile`을 한 트랜잭션에서 지우고(프로필은 내용을 지우고 "다시 만들기" 안내용 빈 표시만 남긴다), 그 원고를 인용한 `outline`의 발췌 블록도 같은 트랜잭션에서 지운다.

### 4.2 암호화 방식
- 데이터 암호화: AES-GCM, 기기별 non-extractable CryptoKey를 `crypto_key` 스토어에 보관한다. 이 키는 JavaScript에서 원문으로 꺼낼 수 없다.
- 키 파생이 필요한 백업 파일: PBKDF2(SHA-256, 600,000회, 솔트 16바이트) 후 AES-GCM. 반복 횟수는 OWASP Password Storage Cheat Sheet의 PBKDF2-HMAC-SHA256 권장값이다(확인 2026-11-05). 가져오기는 파일에 적힌 반복 횟수를 쓴다.
- 평문 localStorage나 sessionStorage에 키나 원고를 두지 않는다.
- 기기 분실이나 브라우저 저장소 삭제 시 암호화 키도 사라진다. 이 경우 원고 복구는 백업 파일로만 가능하다. 이 사실을 온보딩에서 안내한다.

### 4.3 위협과 대응

| 위협 | 대응 |
|---|---|
| 악성 스크립트 실행 | 엄격한 콘텐츠 보안 정책(CSP)으로 외부 스크립트를 차단하고, LLM 출력은 텍스트로만 렌더링한다 |
| LLM 출력의 HTML 삽입(XSS) | 출력은 `textContent`로만 렌더링하고, 마크다운을 쓰면 허용 목록 기반 정제를 거친다 |
| 키 노출 | 키는 암호화 저장, 화면에는 마지막 4자리만 표시, 콘솔과 오류 메시지에 출력하지 않음 |
| 원고 노출 | 기기 암호화, 마스킹 후 저장, 외부 전송은 사용자 동의 후 LLM 호출 시에만 |
| 기기 공유 | 잠금 기능(선택)으로 앱 진입 시 PIN 또는 생체 인증을 요청하는 방식을 검토 |
| 외부 요청 누출 | CSP의 `connect-src`를 제공자 엔드포인트로 제한. 그 밖의 네트워크 요청은 허용하지 않는다 |

### 4.4 외부 전송 규칙
- 외부로 나가는 데이터는 **LLM 호출 요청 본문**뿐이다.
- 호출 요청에 포함될 수 있는 내용: 본문 원문, 키워드, 페르소나 선택값, 사용자가 동의한 발췌 원고, 스타일 프로필 요약.
- 호출 시점에는 이 내용이 제공자로 간다는 것을 화면에 한 번 표시하고 확인을 받는다.
- 설정의 "요청 전 전송 안내 보기"(기본 켜짐)를 끄면 안내 표시만 생략하고 바로 요청한다. 전송 내용은 바뀌지 않으며, 원고 발췌는 끈 뒤에도 `consent_log(external_transfer)` 동의가 있을 때만 넣는다.
- 제공자 응답은 기기 안에만 저장한다.

## 6. 프롬프트 설계

### 6.1 구성 순서
```
[시스템] 역할, 제약 (본문 밖 인용 금지, 교리 단정 금지, 실존 인물 흉내 금지)
[페르소나] 선택값으로 만든 블록
[스타일 프로필] 있을 때만, 원문 없음
[데이터: 참고 발췌] 최대 3개, 내용 복사 금지, 말투와 구성만 참고
[데이터: 본문] 번들 DB에서 가져온 원문 절 목록
[데이터: 키워드] 사용자 입력 또는 본문에서 추출한 3~5개
[출력 형식] 아래 JSON 스키마
```

### 6.2 출력 스키마
```json
{
  "sermon": { "title": "", "body": "", "verse_refs": [] },
  "examples": [ { "text": "", "verse_refs": [] } ],
  "humor": [ { "text": "", "purpose": "" } ]
}
```
- 사용자에게는 "말씀 나눔 초안", "삶에 닿는 예시", "가벼운 한마디"로 표시한다.
- 모델은 구절 문장을 쓰지 않고 인용 자리에 `[[QUOTE 참조]]` 표시만 넣는다(예: `[[QUOTE JHN 15:5]]`). 결과 화면이 그 자리를 번들 DB 원문 인용 블록으로 채운다(규칙 15). 표시 안의 참조도 근거 절 범위 검사를 받고, 길이와 복제 검사에서는 빠진다.

## 7. 검증 규칙

### 7.0 재시도 정책
- 한 번의 생성 요청에서 재시도는 사유(구조, 길이, 근거 절, 복제)를 모두 합쳐 **최대 1회**다(`generation.max_retries_validation`).
- 재시도 후에도 실패하면 검증 실패 결과를 보여주지 않고 독립 모드 결과(말씀 구성표, 라이브러리)로 대체한다.
- 재시도 호출도 `local_limits.daily_llm_calls_per_device`에 포함한다.

### 7.1 구조 검증
- `examples` 2개, `humor` 2개인지 확인한다. 부족하면 재시도한다(7.0).
- 모든 `verse_refs`가 입력 본문 범위 안에 있는지 확인한다.
- 초안 본문 길이가 800~1200자 사이인지 확인한다(3.8 기준: 공백 포함 그래핌 수, 삶에 닿는 예시와 가벼운 한마디는 제외).
- 실존 목회자 이름 패턴이나 "○○ 목사처럼" 표현이 있으면 실패 처리한다.

### 7.2 유머 검증
- 금지 주제: 특정 집단이나 교단 비하, 목회자 조롱, 질병·사망·고난을 웃음거리로 삼는 내용, 성적 농담, 정치적 편향.
- `purpose`가 본문 메시지를 강화하는지 다음 기준으로 자동 판정한다.
  - `purpose`가 비어 있지 않다.
  - `purpose`가 입력 본문 키워드 중 하나 이상을 포함한다.
  - `purpose`와 한마디 본문(`text`)이 금지 주제 키워드 목록에 걸리지 않는다.
- 금지 주제 키워드 목록은 위 5개 주제별로 ko/en 두 벌을 `config`에 둔다. 목록 수정은 config만 고친다.
- 기준을 충족하지 못하면 가벼운 한마디를 빼고 삶에 닿는 예시만 보여준다.

### 7.3 복제 검사
- **비교 대상(원천)**: 참고 발췌(사용자 원고 청크), 가져온 txt 역본 본문(3.14).
- **검사 대상**: 생성 결과 중 본문 인용 블록을 뺀 텍스트. 번들 역본(개역한글, KJV)의 인용 블록은 검사에서 제외한다(3.12에 따라 원문 그대로 표시하기 때문).
- 연속 20자(`sermon_ingest.copy_check_ngram_chars`) 이상 일치하는 구간이 있으면 감지한다. 비교 전에 공백과 문장부호를 정규화한다.
- 감지되면 일치한 발췌를 빼고 재시도한다(7.0의 1회 안에서). 다시 감지되면 독립 결과로 대체한다.
- 독립 모드의 말씀 구성표에는 사용자가 빈칸에 쓴 텍스트에만 같은 검사를 적용한다(3.4).

## 8. 화면 구성

0. **메뉴**: 화면 위쪽 고정 헤더와 탭을 두지 않는다. 화면 구석의 플로팅 메뉴 버튼(44×44px 이상, 본문을 가리지 않는 위치)을 누르면 옆에서 사이드 메뉴가 열린다: 홈, 성경 읽기, 내 설교, 설정, 만든이(3.17). 메뉴 밖을 누르거나 뒤로 가기, 항목 선택으로 닫힌다. 마법사 화면에서는 메뉴 버튼을 숨긴다.
1. **홈**: 오늘의 본문(목록에서 순환), 검색창, 내 설교 빠른 진입
   - 오늘의 본문 목록은 `config`의 `home.daily_verses`에 참조 문자열(책 코드 형식, 예: `JHN 3:16`)로만 둔다. 본문은 번들 DB에서 읽고, 기기 날짜(로컬 자정 기준 일수 % 목록 길이)로 하루에 하나씩 돌린다. 목록의 모든 참조가 krv·kjv에 있는지 테스트한다.
2. **뷰어**: 한 줄 도구 막대(책·장, 역본, 검색), 절 목록. 절을 길게 누르면 선택 모드, 하단 액션 바(주 버튼 말씀 나눔 초안 / 복사 / 말씀 구성표 / 삶에 닿는 예시 / 가벼운 한마디 / 내 설교에서 찾기)
3. **결과 패널**: 말씀 나눔 초안, 삶에 닿는 예시, 가벼운 한마디. 근거 절 링크, "AI가 만든 초안입니다. 고쳐 쓰시면 더 좋아요." 안내
4. **내 설교**: 업로드, 목록, 삭제, 스타일 프로필 상태
5. **설정**: 설정 마법사 다시 열기, 역본 관리(txt 가져오기, 삭제, 역본 안내와 내려받기), UI 언어(한국어 / English), 글자 크기(3.16), LLM 제공자와 키 등록(마스킹), 외부 전송 안내, 백업 내보내기와 가져오기, 로컬 사용 통계, 개인정보 안내
6. **푸터**: 본문 출처와 저작권 표기, 앱 버전

## 9. 저작권과 출처

- 번들 본문: 개역한글(공공 도메인), KJV(퍼블릭 도메인). 출처는 crizin/bible-db 특정 태그로 표기하고, 뷰어 푸터와 앱 설정 화면에 표시한다.
- 개역한글은 저작인격권을 존중해 본문을 바꾸지 않고, 출처를 "성경전서 개역한글판 (대한성서공회)"로 표기한다(bible-db NOTICE).
- KJV는 미국 등에서는 퍼블릭 도메인이지만 영국에서는 Crown copyright(Cambridge University Press) 대상이다. 영국 배포 전에 다시 확인한다.
- 번들 DB에는 개역한글과 KJV 본문만 넣는다(2.1.1). bible-db의 CC BY / CC BY-SA 데이터(원어 태깅, 사전, 의미 벡터 등)는 배포하지 않는다.
- NIV는 기본 번들 대상에서 제외한다. 라이선스 확보 전까지 번들, 배포, 생성 프롬프트 인용 모두 하지 않는다.
- 개역개정, 쉬운성경, 메시지 등 권리 있는 역본은 MVP에서 제외한다. 추가하려면 출판사 허락을 먼저 받는다.
- 사용자가 가져오는 txt 역본(3.14)은 앱이 제공하지 않는다. 배포와 백업 기본값에서 제외하고, 권리 확인 체크를 받는다.
- txt 내려받기 링크는 퍼블릭 도메인으로 확인된 것만 둔다(3.15).
- 앱을 배포하면 번들된 본문도 함께 배포된다. 이 점을 배포 전에 다시 확인한다.
- 생성된 초안과 예시는 앱이 만든 텍스트로 표시하고, 본문 인용은 구분해서 표시한다.

## 10. 비기능 요구사항

- 본문 장 조회: 기기 안에서 200ms 이내
- 첫 화면 표시: 앱 실행 후 1.5초 이내. 첫 화면은 DB 로딩을 기다리지 않는다. 번들 DB(9.8MB)는 분할하지 않고 뷰어가 처음 열릴 때 앱 패키지에서 읽어 메모리에 연다(지연 로딩). 네트워크가 필요 없다.
- 롱터치 인식 지연: 450ms, 체감 지연 없음
- 오프라인: 앱을 설치하면 독립 모드 전체가 오프라인에서 동작
- 터치 타깃: 최소 44×44px
- 화면 폭: 360px 이상에서 가로 스크롤 없음
- 외부 요청: LLM 제공자 엔드포인트 외에는 없음(네트워크 탭으로 검증)
